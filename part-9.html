Control Flow

Workflows vs. Agents

Not every AI application is an "Agent." The fundamental difference lies in who writes the rules. If your code defines the path, it's a Workflow. If the LLM dynamically decides the path, it's an Agent.

The Workflow (Pipeline)

A predefined sequence of steps. The LLM acts as a specific processing node within a hardcoded graph (DAG). The control flow is deterministic and predictable.

Code controls the flow -> LLM executes a task.

The Agent

An autonomous system where the LLM is the orchestration engine. It receives a goal, reasons about it, picks tools, observes results, and plans its next step dynamically in a loop.

LLM controls the flow -> Code executes the tools.

When to use which?

AI Engineering is moving towards a hybrid approach. You don't want agents for everything (they hallucinate and loop), and you don't want workflows for everything (they break on edge cases).

Use Workflows When:

  • The task is repetitive and highly predictable.
  • Latency and cost are critical (agents make multiple expensive LLM calls).
  • You need 100% guarantee on the order of execution.
  • Example: Summarizing daily news and sending an email at 8 AM.

Use Agents When:

  • The path to the goal is ambiguous or requires research.
  • Error recovery is needed (e.g., if a search fails, try a different query).
  • The task requires dynamically choosing between dozens of different tools.
  • Example: "Find me the best laptop under $1000 that has 32GB RAM."
