Taming the Language Model

LLMs love to talk. But software needs precise, predictable data structures. Structured Output is how we force an AI to stop generating conversational text and start generating machine-readable JSON.

1

The Chaos of Chat

If you ask a standard LLM to output JSON, it almost always includes conversational filler (Markdown tags, greetings, explanations). When your application tries to parse this string into a native object using JSON.parse(), your code crashes.

System Prompt
Extract the user's name and age from this text: "Hi I'm Alex and I just turned 24."

Output ONLY as JSON.
Standard LLM Output
CRASH RISK
Sure thing! Here is the JSON you requested based on the provided text:

```json
{
  "name": "Alex",
  "age": 24
}
```

Let me know if you need anything else!
SyntaxError: Unexpected token 'S', "Sure thing"... is not valid JSON at JSON.parse

How does it actually work?

It's not just prompting. Frameworks use a technique called Grammar Constraints (or Guided Generation). Before the model generates the next token, the engine evaluates the schema. Any token that would violate the JSON schema has its probability forcefully set to zero.

// Schema expects "age" to be an integer
{
  "name": "Sarah",
  "age":
Next Token Probabilities
" 28"
85%
"twenty"
12% MASKED
" Sure"
3% MASKED

Because the schema strictly expects an integer after "age":, the engine intercepts the generation loop and blocks the model from outputting strings, conversational words, or brackets. It forces the path to valid syntax.
