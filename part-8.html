The Evaluator-Optimizer Pattern

Sometimes getting the right answer on the first try is impossible. The Evaluator-Optimizer pattern creates a feedback loop: one agent generates a solution, and a second agent critiques it against explicit criteria. They iterate until the output passes the quality gate.

When to use Evaluator-Optimizer

This pattern adds cost (multiple LLM calls) but significantly boosts quality. Use it when evaluation criteria are explicit and machine-checkable, and iterative refinement provides measurable value.

The Roles

  • Generator: Produces the initial output and subsequent revisions based on feedback.
  • Evaluator: Critiques the output against set criteria and returns structured feedback (e.g., JSON with verdict and issues).
  • Termination Condition: The loop ends when the Evaluator returns `PASS` or a max round limit is hit.

Evaluator Strategies

  • Same Model, Different Prompt:
    Lower cost, but the evaluator might inherit the generator's blind spots.
  • Different Model:
    Higher cost, but provides a fully independent perspective (e.g., a fast model generates, a large reasoning model evaluates).
Python Implementation Concept
def optimize_loop(task, max_rounds=3): draft = generator.generate(task) for round_num in range(max_rounds): # Evaluator critiques the draft feedback = evaluator.evaluate(task, draft) if feedback.verdict == "PASS": return draft # Generator revises based on feedback draft = generator.revise(draft, feedback.issues) return draft # Or raise an error if unresolved
