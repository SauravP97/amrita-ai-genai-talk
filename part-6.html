The Routing Pattern

One massive prompt to handle everything is slow, expensive, and unreliable. Routing acts as the intelligent traffic controller of your application, analyzing user intent and instantly directing it to a smaller, highly specialized expert agent.

How do we build the Router?

There are two primary ways to implement a routing layer in an AI application. The choice depends on your latency requirements and complexity.

Logical Routing (LLM-based)

Uses a fast, cheap LLM (like Gemini Flash) provided with a strict prompt and response_schema. It reads the input and outputs a structured JSON response deciding the category.

// System Prompt Example
Analyze the user input and classify the intent into one of the following exact strings: ["code", "support", "rag", "chat"].

Input: "Write a python script..."
Output: "code"
  • Highly accurate, can reason through ambiguity.
  • Slower (adds LLM inference time overhead).

Semantic Routing (Vector-based)

Converts the user query into a vector embedding. It then calculates the mathematical distance between the query and pre-defined embedding clusters for each route.

// Vector Similarity Example
User_Embed = get_embedding("My order #8922...")

distance_to_support = cosine_sim(User_Embed, Support_Cluster)
distance_to_code = cosine_sim(User_Embed, Code_Cluster)

Route -> Max Similarity (Support)
  • Lightning fast, almost zero latency.
  • Less flexible with highly nuanced or mixed intents.
